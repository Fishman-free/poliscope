# Poliscope 决赛前架构评审与迭代路线

日期：2026-10-09。依据仓库设计规格、应用入口、议会、证据门、模型与工具网关、前端工作台、评测代码及相关测试核查。此文档区分已验证行为与尚待实测的目标。

## 1. 当前拓扑与契约

```text
研究者确认原子主张
  → API 建任务、持久化预算与状态
  → Worker / CouncilOrchestrator 按阶段推进
      → 七席各持角色指令、私人记忆和证据投影
      → Model Gateway / Tool Gateway
      → 席位输出结构化科研动作；失败则记录缺席及未完成槽位
  → Scientific Event Ledger
  → Evidence Gate 六阶段审计
  → Graph Projector 唯一写 Evidence Graph
  → 工作台：SSE 过程流 + 已提交快照 + 审计/地图/报告
```

这是**层级式编排 + 每阶段七席收集**，不是 mesh。`_collect` 当前逐席等待，因此“七席”在执行时间上并非并行 fan-out。没有投票判定科学真理；证据门和图投影器决定哪些主张可进入正式图。科学家的输出契约由 `PHASE_OUTPUT_SCHEMAS` 和阶段处理器约束，`Model Gateway` 做结构校验，失败输出隔离。API、Worker 和 Projector 的数据库权限边界值得保留。

当 Agent B 超时：单次调用最多 120 秒，阶段收集有 15 分钟上限；在上限内最多询问 3 次并退避；仍失败时生成 `SEAT_UNAVAILABLE` 和未完成槽位，继续其余席位，最终标记有缺口。结构无效时走流式失败 → 有界普通调用与一次 schema 修复 → 隔离/缺席。该恢复路径已有测试，但没有实际 DeepSeek 生产压测数据。

## 2. 本次已落地的修复

| 问题 | 修复 | 验证 |
|---|---|---|
| DeepSeek / OpenAI 兼容流断线仍可能被当成成功 | 模型网关和补充提问只在收到 `[DONE]` 后成功；`finish_reason=length` 作为不完整结果；补充提问设置总时限 | 新增中断与截断回归用例 |
| 浏览器补充提问在 EOF 时误报成功；失败后清空已收到内容 | EOF 报错；保留并标记不完整文本；按动画帧合并 delta，减少每 token 重渲染 | 前端类型检查与构建 |
| 地图 CSS 多余 `}`，导致压缩器语法警告 | 删除多余声明块 | 构建不再报 CSS 语法错误 |
| 未随仓库分发的商业字体造成构建警告与无效请求 | 移除该字体引用，保留现有衬线回退 | 构建不再报字体缺失 |
| 首屏加载完整 React Flow 地图代码 | 地图按需加载，提供加载态 | 入口 JS 约 654 → 441 KB；地图独立约 214 KB |
| 审计 `request_summary` 保存完整 prompt / 工具参数 | 改为固定元数据白名单；输入哈希和计费字段仍在 | 新增敏感文本回归用例 |
| 无 `claim_id` 的 StudyFinding 可能绕过因果升级检查 | `FullEvidenceGate` 也审查显式 `claim_type` 与研究设计 | 原有回归用例通过 |
| 无原文引句的 StudyFinding 进入投影阶段后因悬空来源边报错 | 证据门在引用审核阶段隔离无引句记录，并保留失败审计 | 单元与 PostgreSQL 投影集成测试通过 |
| 完整测试曾被 Docker 标记全部跳过 | 将标记限定在集成测试目录，并新增标记范围回归测试 | 完整测试实际执行，详见下方结果 |
| 免费试用集成测试仍断言旧 DashScope 配置 | 按现行 DeepSeek 端点、模型和请求字段更新测试 | 相关集成测试通过 |

受影响的 50 项单元及数据库集成测试通过；完整测试集 **1218 项通过，无失败或跳过**（约 5 分 47 秒）。前端生产构建通过，修改文件的静态检查通过。未获取真实 DeepSeek 密钥，故未进行厂商流式实测；真实浏览器视觉走查也受环境限制。

## 3. 决赛前优先级

### P0：证明核心主张，经得起质询

1. **把评测语料做成可复跑基准。** 当前 `load_case_inventory()` 只有 2 条示例，而仓库规范要求每席 ≥20 例。先完成至少 20 个封闭语料案例，覆盖混杂、反向因果、测量偏差、同源重复、撤稿、摘要替代全文、文献互相矛盾、无来源、预算不足和恶意文档。固定模型版本、温度、语料截止日、标注者和判定标准，保存每席及全流水线基线分数。重点报告 Blindspot Recall/Precision、错误因果升级率、引用蕴含、异议保留率、每个有效盲点成本；不要把脚本化 demo 得分说成真实世界效果。
2. **做一次真实 DeepSeek + PostgreSQL 端到端跑通。** 当前 Worker 使用 PostgreSQL 任务队列，Redis 不是运行前提。记录首 token、每阶段和全程 p50/p95 延迟；模拟断流、429、5xx、一个席位超时、浏览器重连、Worker 中途重启。验证缺席、快照恢复和最终报告中的缺口一致。上线演示用经过复跑的固定案例及同样的模型配置。
3. **把决赛讲述收束到一次盲点发现。** 30 秒呈现研究问题、一个可核验原文、七席分歧、被证据门拒绝的因果跃迁、最终盲点与判别研究。用户应能从结论点击回来源及审计记录；不要靠七张实时聊天卡证明多智能体价值。

### P1：把 demo 的可靠性变成可追责的系统

1. **跨跳 trace。** 现有 `task_id` 与模型/工具审计表可定位任务，缺少一次运行唯一 `trace_id`、每次调用的 `span_id` 和父子关系。重新研究会复用 task，因此 `task_id` 不能替代 run trace。为 API → Worker → 席位 → 网关 → 证据门 → Projector 建立结构化 span，记录开始/结束、状态、重试、模型、token、成本、输入哈希；审计摘要继续禁止保存原始 prompt、凭证及上传材料。
2. **收窄权限与不可信内容边界。** 当前七席共享网关，尚需可执行的“席位 × 工具操作”允许表；外部网页、PDF 和下载的 Skill 文本应作为带来源标记的数据进入 user context，不能获得 system 指令权。模型输出经 schema 校验，但这本身不能证明没有提示注入。补充 20 个注入对抗用例，检查是否能诱导调用越权工具、改变证据准入或泄露凭证。SSE 使用 URL 查询参数传 bearer token，也应改成短期、单用途流令牌或同站 HttpOnly Cookie，避免进入访问日志和历史。
3. **上下文预算必须覆盖每席输入。** 目前有费用、时间、工具、来源预算及若干字符截断，但缺少逐席模型 token 预算与必需字段检查。明确每阶段必需字段（主张 ID、来源锚点、未解决异议、证据状态），先按字段压缩；若仍超预算则显式停止该席并记录缺口，不能静默截断。快照中不放 API Key、原始上传材料或其他敏感数据。
4. **停止暴露原始私有推理。** 当前 `MODEL_REASONING_CAPTURED` 和 `model_reasoning` 会把供应商原始 reasoning 保存并呈现；这与项目 `AGENTS.md` 的前端约束冲突。应只公开结构化动作、证据、质询、决策摘要和状态变化。实施前评估现有过程审计与重放需求，并迁移旧事件的展示方式。

### P2：提高多智能体协作效率与观感

1. **仅在独立阶段做有界并行。** 当前 `_collect` 逐席执行，有天然的延迟叠加；预承诺和独立取证适合 fan-out，交叉质询仍需等待前序结果。先把每席输入固定为不可变快照、每席单独 DB session/写入队列，再尝试 2–3 席并发，量化 p95 延迟、缺席率、API 429 和每有效盲点成本。禁止让并发席位共享可变 `PhaseContext` 或数据库会话。若部分结果到齐，综合器必须明确写出缺席与未审查槽位；零结果时降级报告，不能造共识。
2. **视觉层级围绕证据地图。** 保留“结论与局限并排”、证据色语义及可追溯路径。实机验收 390/768/1440 px 的地图节点可读性、地图与侧栏拥挤、焦点顺序、缩放与触屏手势、浅色对比度，以及流式大量输出时的滚动控制。当前只完成源码/构建检查，未完成真实浏览器视觉验收。
3. **减少用户等待时的不确定感。** 排队、运行、降级、人工检查点和报告中断需要清晰状态、最近成功检查点、预计下一步、可重试动作；不要以原始思维链填满空白。统计首可见进展、首可靠证据、最终报告三个时间指标。

## 4. 上线门控与故障注入清单

| 注入 | 期望恢复与可见结果 |
|---|---|
| 单席 120 秒超时 / 429 | 有界重试；记录次数和原因；其余席位继续；报告含缺口 |
| 流式 EOF、`length`、无输出 | 不标记完成；保留已收到的片段但标注不完整；可重新发起 |
| 结构字段或原文引句缺失；引句不支持结论 | 缺失时隔离；蕴含失败时降级并记录缺陷；不把未经核验的结论标成正式证据 |
| 同数据集的多篇论文 | 谱系折叠为独立证据簇，不重复计票 |
| 恶意网页 / Skill / PDF 文字 | 不改变角色、工具权限和证据门；记录来源及被拒绝动作 |
| Worker 进程中断、SSE 重连 | 从持久检查点恢复；事件幂等；浏览器重放后状态一致 |
| 七席全部不可用 | 产出结构化降级报告，说明未调查的证据槽位 |

发布条件：每席至少 20 个有代表性的 eval 案例；记录旧版基线与新版分数；全流水线回归通过；真实模型和数据库故障注入通过；浏览器视觉检查完成。若其中任何一项缺失，只可称为经过代码级验证的候选版本。
