# Poliscope

> **阅读语言 / Language / 語言：** [简体中文](README.md) · [繁體中文](README.zh-Hant.md) · [English](README.en.md)

> 七位 AI 科学家，一场没有和稀泥的科研审查。欢迎来到现场。
>
> **在线体验：** [https://poliscope.tech/](https://poliscope.tech/) — 作者部署的公开实例，打开即用，无需安装
>
> **学术论文：** [《EpistemoBrain: A Seven-Scientist Council with Dual-Graph Evidence Governance for Auditable Scientific Blindspot Discovery》](docs/paper/epistemobrain.pdf)（ACL Findings 2026 格式，`docs/paper/epistemobrain.tex`，[PDF 直下](docs/paper/epistemobrain.pdf)）

想象一下这个场景：你正在审阅一篇「社交媒体导致青少年抑郁」的研究。结论很漂亮，引用很齐全——但没有人告诉你，这篇论文和另外五篇用的是同一份数据；没有人告诉你，关键的因果表述其实只是相关；也没有人告诉你，作者自己都承认没排除反向因果。

Poliscope 就是为这个场景造的。它是一个面向计算社会科学争议问题的**深度研究智能体**：输入一个存疑的问题，它组织 **7 名各有专长的 AI 科学家**独立取证、互相质询、专门找反例和漏洞，最后产出一张**结论与局限并排、证据可溯源、异议不删除**的争议证据地图。

不是一段读起来通顺、但无法核验的总结。

## 一、设计思路：Poliscope 为什么长这样

### 1. 今天发布的不是「7 个聊天机器人 + 1 个总结机器人」

这是 Poliscope 最容易被误解的地方，所以值得在第一分钟讲清楚：让 7 个 Agent 轮流各说一段话、再让第 8 个 Agent 写摘要，做出来的东西看起来热闹，但**解决不了任何一个真实的科研盲点问题**——分歧会在总结那一步被拍平，没人的判断真正被别人的证据挑战过。

Poliscope 的设计从一开始就是反着来的：先决定「一个可靠的争议审查该有的组织结构和记忆机制是什么样」，再把 7 个角色放进这套结构里。这套结构叫 **EpistemoBrain**。下面按「为什么这样设计」的逻辑逐层展开。

### 2. 七人全程参与，成本用别的方式控制

任何一次「这个角色这次用不上」的判断，都是在赌盲点不会出现在被跳过的那个维度。测量专家看起来和一场因果争议无关，但自报告偏差往往就是那场因果争议真正的根源。所以 **7 个席位在每个正式研究任务中全程参与**——每轮发言有预算、没有新信息就 `PASS`、语义去重后才触发重推理、七人共享同一份检索缓存。工程上更麻烦，但换来的是「不会因为一次调度误判，漏掉本该被发现的盲点」。

七人分别是：理论建构者、因果推断专家、测量与构念专家、统计与复现专家、边界与情境专家、对抗性证伪者、证据与溯源审计员。EpistemoBrain 是无投票权的组织脑——不是第 8 名科学家，也不代表任何学术立场。

每个席位拥有**独立角色规格、独立私人状态、独立私人记忆和不同的证据排序权重**，取证阶段互不可见，先各自下判断再交换证据——「交叉质询」才是真的交叉质询，不是同一个思路的复述。

### 3. 三层科研记忆：Private → Collective → Evidence

EpistemoBrain 把「记忆」拆成三个层级，每一层回答不同的问题：

```
第一层  Private Brain          每个科学家自己的探索过程、工具记录、未验证猜想
            │ 提交结构化科研事件
            ▼
第二层  Collective MemoBrain  谁提出了什么、谁攻击了什么、哪些争议未解决、下一步该查什么
            │ 验证后沉淀
            ▼
第三层  Controversy Evidence  面向用户的稳定知识产物：可审计的争议证据地图
```

- **第一层 Private Brain**：直接复用 MemoBrain（ACL Findings 2026）的长程记忆能力。每位科学家的短期记忆只服务于自己——当前任务、已访问论文、未验证猜想、工具执行记录、下一步计划。**避免每个智能体因为长时间检索而失去自己的专业任务，同时维持角色差异。**
- **第二层 Collective MemoBrain**：不存储聊天内容，而是存储科学共同体发生过的**结构化认知事件**（谁对哪个主张提出了什么质询、置信度多少、用了什么证据）。它回答：哪些主张仍活跃？哪些证据已被质疑？哪些争议已解决、哪些只是被搁置？哪个盲点还没人调查？下一轮最值得投入 token 的问题是什么？**这已经不是被动记忆，而是一个科研过程的执行控制系统。**
- **第三层 Controversy Evidence Graph**：只保存经过校验、可展示、可审计的科研知识，不包含任何 Agent 的内部思考。

### 4. 异议保真，议会不是投票

**系统禁止用多数投票直接裁决科研真理。** 一个科研判断是不是真的，不取决于七个人里有几个举手。议会按七轮协议运行：

1. **独立预承诺**——七人互不可见地提交初始判断与置信度（先封存、后读取，杜绝「从众」和「事后一致性」）；
2. **专业取证**——按各自的证据需求并行检索与深读；
3. **证据交换**——只交换结构化证据，不交换推理历史；
4. **交叉质询**——针对因果、测量、统计、边界、来源和隐藏假设定向攻击；
5. **盲点悬赏**——给证据图暴露的缺口打分、排序、认领；
6. **联合建模**——产出条件化共识：共同认识、最强正反立场、铰链变量、适用边界、未解决冲突与证伪条件；
7. **最终复判**——七人再次独立判断，记录信念如何被证据改变，以及谁仍然持异议。

被反驳、被隔离的观点不会消失，仍可追溯；最终结果表达为**条件化共识**，真正的分歧会被写成具名的**异议证书（Dissent Certificate）**，而不是被多数意见悄悄吞掉。你可以在网页上看到每一次质询、每一次立场变化、每一位科学家最后坚持了什么。

MemoBrain 的三个原生动作，在这里被重新定义为科研语义：

- **Flush → Quarantine（隔离，不是清空）**——被反驳的主张不会消失，只换状态，并记录是谁反驳的、缺什么证据、满足什么条件可以复活；
- **Fold → Dialectical Fold（辩证折叠，不是压缩字数）**——一场争议只有在保留共同认识、最强支持、最强反对、铰链变量、适用边界、未解决冲突与证伪条件之后，才被折叠成一个辩论胶囊（DebateCapsule），原始节点仍在，随时可以点回原文；
- **Recall → Perspective Recall（角色化召回）**——每位科学家拿到的是自己的私有过程记忆 + 从同一张证据图生成的、专属于自己关注维度的切片：因果专家看到混杂和反向因果，测量专家看到构念冲突。

### 5. 双图治理——过程和结论必须分开存放

七人在取证、质询、犯错、走弯路的全过程都会被记下来（**Process Graph**，由执行记忆管理），但这些「过程」不能自动变成「事实」——不然一个科学家一时的错误猜测，可能悄悄升级成报告里的正式结论。

所以所有正式修改必须先写入**科研事件账本**（Scientific Event Ledger），再由唯一的写入者 **Graph Projector** 审核后落地到 **Evidence Graph**（争议证据地图：原子主张、研究发现、来源、构念、盲点、辩论胶囊……）。这一步在**数据库权限层面**强制，不是靠代码自律——七名科学家在数据库层面根本没有写证据图的权限，哪怕程序有 bug 也碰不到正式证据。

为什么需要双图而不是一张图？因为「这位科学家是怎么完成研究的」和「我们现在对这个研究问题知道什么」是两个不同的问题。工具调用步骤和学术证据混在一张图里，就分不清谁是过程、谁是证据；一次压缩历史也可能把还没解决的争议一起压掉。分两张图，过程可以折叠、证据永不丢失。

### 6. 证据门——每一条正式结论都要过六道审核

候选事件依次通过：**Schema 校验 → 语义去重 → 来源核验 → 引用蕴含 → 方法质量 → 图一致性**。具体来说：

- **证据分层**：只有全文与精确原文可得才算 **Level A**；只有摘要、二手描述或新闻线索的会诚实降级，绝不允许摘要单独支撑高置信因果结论；
- **引用蕴含**：论文引言里的假设、讨论段里的推测、作者未检验的机制，都不许被写成实证结果；横截面数据不许被包装成因果证据（`CausalUpgradePolicy` 专门拦这个组合）；
- **三层审计**：来源真实性、引用蕴含、方法质量，逐条核验；
- **精确溯源**：每个正式 `StudyFinding` 至少绑定来源、研究、章节、页码（或等价定位）、原文引用、抽取 Agent 和核验状态，每个关键判断都能点回原文。

### 7. 论文数量 ≠ 独立证据数量

六篇论文如果共享同一份数据集、同一个研究团队、或者一篇是另一篇的扩展，本质上是一份证据被讲了六遍。证据谱系（Evidence Lineage）自动识别**同一数据集 / 重叠样本 / 预印本与正式版 / 扩展研究 / 综述包含的原始研究**这些依赖，界面同时展示「论文数量」和「独立证据簇数量」——这两个数字第一次被分开摆出来，你才看得出一个「共识」到底是七次独立观察，还是一次观察被转述了七遍。

此外还有四道防线防止「七个人共享同一个证据错误」：盲证据评审（隐藏作者与期刊声誉信号）、独立双抽取（高影响发现由两条路径分别抽取）、来源多样性约束（全部证据同源时自动标记盲点）、对抗式检索（主动找反驳、零结果、复现失败，而不是只找支持自己的论文）。

### 8. 认识论路由——让证据图自己决定下一步查什么

议会不是机械地跑满七轮就算完成。证据图发现的缺口会生成**盲点悬赏**，按影响、不确定性、可调查性、新颖度和成本打分排出优先级，再广播给七人认领——**是证据状态在驱动下一步调查方向，而不是主持人按预定台本依次点名发言**。这也是为什么 Blindspot 是产品里的一等公民对象，而不是报告末尾一段「局限性」文字。

## 二、应用场景：它解决什么问题

### 面向研究者：选题、综述与研究设计

Poliscope 不是替你写文字，而是替你**发现混杂、边界、测量问题和冲突证据**：

- **写综述前**：输入你的争议问题，让它先画一张「哪些证据支持、哪些反对、哪里是同源重复、哪里是真空」的地图——你会带着一张缺口清单开始阅读，而不是从头读起；
- **评估一篇论文**：上传 PDF 做论文审查，议会逐项指出论证不严谨、证据不充分、测量与样本代表性问题，并给出可操作的改进建议；
- **设计下一步研究**：证据图里未被解决的盲点，会被翻译成一个具体的**判别研究（DiscriminatingStudy）**——用什么样的数据、控制什么变量、能区分哪两种竞争解释。系统从「指出问题」走向「提出可执行的研究方案」。

### 面向评审与答辩：可审计，不裸奔

每一句关键判断都能点回原文位置；每一次立场变化、每一个保留的异议都留痕。你展示的不是「AI 给了一段漂亮的总结」，而是**一个可追溯、可证伪的科研过程**。

### 面向心智健康等敏感议题：科研辅助，不是临床诊断

涉及心理健康的问题，报告会明确标注「这是科研辅助，不是临床诊断」；系统不会为了显得「有结论」而编结论。

## 三、产品优势

- **每个关键判断都能点回原文。** 每个正式 `StudyFinding` 至少绑定来源、研究、章节、页码（或等价定位）、原文引用、抽取 Agent 和核验状态，经过来源真实性、引用蕴含、方法质量三层审核才能进图。
- **论文数量 ≠ 独立证据数量。** 六篇论文如果共享同一份数据集或同一个实验室的样本，只算一份独立证据——报告里这两个数字分开显示。
- **诚实报告缺口，而不是伪造完整结果。** 模型供应商没配好、预算耗尽、某个席位缺席，都会在报告里逐条列出，任务状态显式标记为「带缺口完成」——空白永远不等于没问题。
- **证据强度分级。** Level A（全文与精确原文可得）到 Level D（网页/新闻线索）四级全标出，Level B/C/D 不会被用来单独支撑高置信因果结论。
- **异议永久保留，不靠多数票压下去。** 联合建模禁止用投票裁决科研真理；被反驳、隔离或折叠的观点仍可追溯，持异议的科学家会拿到一份具名的 `DissentCertificate`。
- **盲点驱动下一步调查。** 证据图发现的缺口生成「盲点悬赏」，按影响、不确定性、可调查性打分排出优先级，再由七人认领——Blindspot 是产品里的一等公民对象，不是报告末尾一段「局限性」文字。
- **思考链路可见，思维链不裸奔。** 议会页展示每位科学家的完整链路——预承诺 → 各轮次行动 → 最终复判，原始模型推理在对应轮次下折叠展开。系统明确标注：那是过程数据，不是证据。
- **相关不自动升级为因果。** 因果表述必须经过因果审查并明确识别局限，横截面数据 + 因果主张的组合会被证据门直接拦截并留痕。
- **跑完有一份可下载的最终论文。** 任务终态时整合七席终审、条件化共识与全部参考文献，产出结构化论文（摘要 / 正文 / 参考文献 / 局限 / 调查过程），可导出 Markdown。
- **每个缺口都被点名，不只是一个计数。** 哪个席位缺席、哪个轮次未执行或失败，全部用中文名写出来，任务头常驻明细。
- **四个入口，一套内核。** 网页工作台、HTTP/SSE API、命令行 CLI、Claude Code / Codex Agent Skill，全部走同一条研究契约，没有第二条能绕过证据门的路径。
- **队列可见、会话可控。** 排队时明确告诉你前面还有几个任务、Worker 正在跑哪个；会话历史支持单条删除与全部清空，你的数据你做主。

## 四、产品能力一览

研究工作台提供八个视图，产品中心是**证据地图**，不是聊天框：

| 视图 | 回答的问题 |
|---|---|
| **Research Brief** | 30 秒了解：当前判断、证据强弱、反例、盲点和下一项该做的研究 |
| **Controversy Map** | 主张、发现、构念、边界、冲突与盲点组成的可交互证据地图，点击任何节点都能看到人话版详情与原始记录 |
| **Audit Trail** | 完整事件账本：谁在什么时候做了什么判断、用了什么证据 |
| **Council（议会）** | 7 名科学家并排的完整链路：预承诺置信度 → 各轮次行动 → 最终复判，以及条件化共识面板 |
| **Blindspot Radar** | 按影响与可调查性排列的盲点雷达图，点击即读「这个盲点是什么、轻信它有什么后果」 |
| **Evolution View** | 主张与盲点随证据演化的时间线 |
| **最终论文** | 整合结论、参考文献、局限与调查过程的论文式产出，可下载 |
| **知识库** | 你的长期记忆：上传文献、粘贴笔记，检索命中直接参与议会推理 |

## 五、使用方法

### 1. Web 网页：上线两个功能

打开**公开演示实例 `https://poliscope.tech/`**，点「进入工作台」（或直接访问 `/workspace`），注册一个账号即可开始。目前上线两个功能：

- **深度研究**：输入一个存疑的争议问题，七人议会独立取证、交叉质询，产出一张可审计的证据地图；
- **论文审查**：先**上传待审查的论文**（PDF / Word / PPT / Excel / HTML / TXT 等，单个 ≤ 20 MB），议会读清论文的研究问题、主要观点与佐证，再逐项审查论证严谨性、证据充分性、测量与样本代表性，给出改进建议。审查完成后可在「补充提问」里继续追问，模型会基于论文全文回答。

研究过程中页面自动跟随议会进度，跑完后可在网页查看结论，也可导出 Markdown / JSON 报告。

深度研究在联合建模（JOINT_MODELING）之前设有一个**有界的人类方向性引导检查点**：此时 7 名科学家已完成前 5 轮（独立预承诺、取证、证据交换、交叉质询、盲点悬赏），系统暂停等待你提交一段方向性备注（或明确留空继续）。这个检查点**不是投票**，也不会被当成第 8 名科学家的科研判断，只影响联合建模阶段优先讨论哪些悬而未决的冲突。

- **宽限期内**（默认 120 秒，可用 `POLISCOPE_COUNCIL_INPUT_GRACE_SECONDS` 配置，最小 30 秒），你在页面正常提交引导意见即可，人工意见优先；
- **宽限期届满仍未操作**（例如浏览器切到后台或关闭），服务端会自动把任务置回排队，以「无方向性干预」继续联合建模——**研究不会被你走开而卡死**。自动续跑保留全部已完成的议会产物，`guidance` 保持为空，绝不会伪装成你提交过意见；所有状态变更都会刷新 `updated_at`，使宽限从真正进入等待态的时刻起算。

### 2. 从编程 Agent 里直接调用（Skill）

如果你平时在 Claude Code、Codex 或其它支持 `AGENTS.md` 约定的编程 Agent 里工作，不想切换到网页，可以直接让 Agent 调用 Poliscope。仓库里放了四份内容一致的 Skill 副本：

```
skills/poliscope/             Claude Code 插件内的 Skill（/plugin install 后可用）
.claude/skills/poliscope/     Claude Code 的 Agent Skill
.codex/skills/poliscope/      Codex 对应副本
.agents/skills/poliscope/     通用 AGENTS.md 约定读取的副本
```

Skill 本质上都在调用同一个 `poliscope` 命令行工具（Python 3.12）。装法三选一：

**方式一：Claude Code 里 `/plugin install`（推荐，一条命令装好插件 + Skill）：**

```bash
/plugin install Fishman-free/poliscope
```

装完后直接输入 `/poliscope` 即可调用（也可以 `/plugin marketplace add Fishman-free/poliscope` 把它加进市场列表再浏览）。

**方式二：`npx` 零安装运行（有 Node 18+ 即可，底层自动用仓库 venv 或 uvx 拉取 Python CLI）：**

```bash
npx github:Fishman-free/poliscope --help
```

发布到 npm registry 后，`npx poliscope --help` 同样可用。也可以用 Python 生态的等价物直接跑：

```bash
uvx --from "git+https://github.com/Fishman-free/poliscope.git" poliscope --help
```

**方式三：克隆仓库常驻安装：**

```bash
git clone https://github.com/Fishman-free/poliscope.git
cd poliscope
uv sync                       # 或者 pip install -e ".[dev]"
poliscope --help              # 能打印帮助信息就说明装好了
```

Skill 本身不内置任何服务器地址，它调用的命令行默认连 `http://localhost:8000`（本机起的 API）。连已部署实例时每次调用带 `--base-url`，并**先登录一次**：

```bash
poliscope login --base-url <URL>     # 输入用户名密码；首次使用可用 register 注册
```

token 保存在 `~/.poliscope/credentials.json`（一个 base URL 一个 token，30 天过期），之后所有命令自动带上；非交互环境（Agent 脚本）也可以直接设置 `POLISCOPE_API_TOKEN` 环境变量，优先级高于凭据文件。本机 API 不需要登录——`poliscope health` 可以先确认 API 活着。

工作流：你用自然语言描述研究问题 → Skill 生成待确认的 Research Contract（**先给你看，不会直接提交**）→ 你确认后依次调用 `poliscope start`（给出建议主张）→ `poliscope confirm-claims` → `poliscope watch` / `status` → `poliscope export`。连已部署实例时先 `poliscope login` 一次（见上）。任务会返回 `task_id`，换机器、关对话后都能接着查。

完整命令行用法（含 `pause`/`resume`、`council-preview`/`council-guidance`、`export-docs` 等全部子命令）见 [`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md)。

## 六、地址与访问：如果打不开

**症状一：浏览器报「无法访问此页面」「连接已关闭」「此站点连接不安全」。**

现代浏览器（尤其 Edge / Chrome）默认把 `http://` 自动升级成 `https://`。如果网站本身只提供 `http://`（无 HTTPS），升级就会失败，表现为打不开，或从 GitHub 点进去能见首页、但数据加载不出来。

**你只需要这样做（任选其一）：**

- 把地址栏的 `https://` 手动改回 `http://`，回车即可；
- 用浏览器**无痕窗口**访问；
- 在 Edge 设置里关闭「自动使用 HTTPS」（设置 → 隐私、搜索和服务 → 关闭「自动使用 HTTPS」）。

**症状二：打开其他网址（自部署/局域网）打不开。**

问部署方要**正确的地址和端口**（常见是 `http://localhost:8080/`，公网部署则是 `http://<IP>/` 或 `http://<域名>/`），确认后直接访问即可。

## 七、请诚实对待它的结论

- **它不是医疗建议。** 涉及心理健康的问题，报告里会明确标注「这是科研辅助，不是临床诊断」。
- **它不会为了显得「有结论」而编结论。** 如果部署方没配好 AI 模型的访问权限，系统会诚实报告「未接入模型」，某些科学家的判断会显式标记为缺席——空白不等于没问题，这也是它的设计原则。
- **模型置信度不是统计证据。** 报告把模型判断、作者原话和统计推断分开标注，不用模型置信度替代统计不确定性。
- **被反驳、被隔离的观点不会消失。** 报告里的分歧和反例都留着原文出处，你可以自己判断该信哪一边。
