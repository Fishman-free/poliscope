# Poliscope

> **閱讀語言 / Language / 語言：** [简体中文](README.md) · [繁體中文](README.zh-Hant.md) · [English](README.en.md)

> 七位 AI 科學家，一場沒有和稀泥的科研審查。歡迎來到現場。
>
> **線上體驗：** [http://39.96.197.238/](http://39.96.197.238/) — 作者部署的公開實例，打開即用，無需安裝

想像一下這個場景：你正在審閱一篇「社群媒體導致青少年憂鬱」的研究。結論很漂亮，引用很齊全——但沒有人告訴你，這篇論文和另外五篇用的是同一份資料；沒有人告訴你，關鍵的因果表述其實只是相關；也沒有人告訴你，作者自己都承認沒排除反向因果。

Poliscope 就是為這個場景造的。它是一個面向計算社會科學爭議問題的**深度研究智慧體**：輸入一個存疑的問題，它組織 **7 名各有專長的 AI 科學家**獨立取證、互相質詢、專門找反例和漏洞，最後產出一張**結論與局限並排、證據可溯源、異議不刪除**的爭議證據地圖。

不是一段讀起來通順、但無法核驗的總結。

## 一、設計思路：Poliscope 為什麼長這樣

### 1. 今天發布的不是「7 個聊天機器人 + 1 個總結機器人」

這是 Poliscope 最容易被誤解的地方，所以值得在第一分鐘講清楚：讓 7 個 Agent 輪流各說一段話、再讓第 8 個 Agent 寫摘要，做出來的東西看起來熱鬧，但**解決不了任何一個真實的科研盲點問題**——分歧會在總結那一步被拍平，沒人的判斷真正被別人的證據挑戰過。

Poliscope 的設計從一開始就是反著來的：先決定「一個可靠的爭議審查該有的組織結構和記憶機制是什麼樣」，再把 7 個角色放進這套結構裡。這套結構叫 **EpistemoBrain**。下面按「為什麼這樣設計」的邏輯逐層展開。

### 2. 七人全程參與，成本用別的方式控制

任何一次「這個角色這次用不上」的判斷，都是在賭盲點不會出現在被跳過的那個維度。測量專家看起來和一場因果爭議無關，但自報告偏差往往就是那場因果爭議真正的根源。所以 **7 個席位在每個正式研究任務中全程參與**——每輪發言有預算、沒有新資訊就 `PASS`、語義去重後才觸發重推理、七人共享同一份檢索快取。工程上更麻煩，但換來的是「不會因為一次調度誤判，漏掉本該被發現的盲點」。

七人分別是：理論建構者、因果推斷專家、測量與構念專家、統計與複現專家、邊界與情境專家、對抗性證偽者、證據與溯源審計員。EpistemoBrain 是無投票權的組織腦——不是第 8 名科學家，也不代表任何學術立場。

每個席位擁有**獨立角色規格、獨立私人狀態、獨立私人記憶和不同的證據排序權重**，取證階段互不可見，先各自下判斷再交換證據——「交叉質詢」才是真的交叉質詢，不是同一個思路的複述。

### 3. 異議保真，議會不是投票

**系統禁止用多數投票直接裁決科研真理。** 一個科研判斷是不是真的，不取決於七個人裡有幾個舉手。議會按七輪協議運行：

1. **獨立預承諾**——七人互不可見地提交初始判斷與置信度（先封存、後讀取，杜絕「從眾」和「事後一致性」）；
2. **專業取證**——按各自的證據需求並行檢索與深讀；
3. **證據交換**——只交換結構化證據，不交換推理歷史；
4. **交叉質詢**——針對因果、測量、統計、邊界、來源和隱藏假設定向攻擊；
5. **盲點懸賞**——給證據圖暴露的缺口打分、排序、認領；
6. **聯合建模**——產出條件化共識：共同認識、最強正反立場、鉸鏈變數、適用邊界、未解決衝突與證偽條件；
7. **最終複判**——七人再次獨立判斷，記錄信念如何被證據改變，以及誰仍然持異議。

被反駁、被隔離的觀點不會消失，仍可追溯；最終結果表達為**條件化共識**，真正的分歧會被寫成具名的**異議證書（Dissent Certificate）**，而不是被多數意見悄悄吞掉。你可以在網頁上看到每一次質詢、每一次立場變化、每一位科學家最後堅持了什麼。

### 4. 雙圖治理——過程和結論必須分開存放

七人在取證、質詢、犯錯、走彎路的全過程都會被記下來（**Process Graph**，由執行記憶管理），但這些「過程」不能自動變成「事實」——不然一個科學家一時的錯誤猜測，可能悄悄升級成報告裡的正式結論。

所以所有正式修改必須先寫入**科研事件帳本**（Scientific Event Ledger），再由唯一的寫入者 **Graph Projector** 審核後落地到 **Evidence Graph**（爭議證據地圖：原子主張、研究發現、來源、構念、盲點、辯論膠囊……）。這一步在**資料庫權限層面**強制，不是靠程式碼自律——七名科學家在資料庫層面根本沒有寫證據圖的權限，就算程式有 bug 也碰不到正式證據。

為什麼需要雙圖而不是一張圖？因為「這位科學家是怎麼完成研究的」和「我們現在對這個研究問題知道什麼」是兩個不同的問題。工具呼叫步驟和學術證據混在一張圖裡，就分不清誰是過程、誰是證據；一次壓縮歷史也可能把還沒解決的爭議一起壓掉。分兩張圖，過程可以摺疊、證據永不丟失。

### 5. 證據門——每一條正式結論都要過六道審核

候選事件依序通過：**Schema 校驗 → 語義去重 → 來源核驗 → 引用蘊含 → 方法品質 → 圖一致性**。具體來說：

- **證據分層**：只有全文與精確原文可得才算 **Level A**；只有摘要、二手描述或新聞線索的會誠實降級，絕不允許摘要單獨支撐高置信因果結論；
- **引用蘊含**：論文引言裡的假設、討論段裡的推測、作者未檢驗的機制，都不許被寫成實證結果；橫斷面資料不許被包裝成因果證據（`CausalUpgradePolicy` 專門攔這個組合）；
- **三層審計**：來源真實性、引用蘊含、方法品質，逐條核驗；
- **精確溯源**：每個正式 `StudyFinding` 至少綁定來源、研究、章節、頁碼（或等價定位）、原文引用、抽取 Agent 和核驗狀態，每個關鍵判斷都能點回原文。

### 6. 論文數量 ≠ 獨立證據數量

六篇論文如果共享同一份資料集、同一個研究團隊、或者一篇是另一篇的擴展，本質上是一份證據被講了六遍。證據譜系（Evidence Lineage）自動識別**同一資料集 / 重疊樣本 / 預印本與正式版 / 擴展研究 / 綜述包含的原始研究**這些依賴，介面同時展示「論文數量」和「獨立證據簇數量」——這兩個數字第一次被分開擺出來，你才看得出一個「共識」到底是七次獨立觀察，還是一次觀察被轉述了七遍。

此外還有四道防線防止「七個人共享同一個證據錯誤」：盲證據評審（隱藏作者與期刊聲譽訊號）、獨立雙抽取（高影響發現由兩條路徑分別抽取）、來源多樣性約束（全部證據同源時自動標記盲點）、對抗式檢索（主動找反駁、零結果、複現失敗，而不是只找支持自己的論文）。

### 7. 長期記憶：MemoBrain 基座 + 你的知識庫

七人議會的執行記憶基座是 [MemoBrain](https://github.com/qhjqhj00/MemoBrain)（ACL Findings 2026）：每位科學家有獨立的私人記憶，按各自角色取景地回憶證據；被反駁的假設進入隔離區，滿足復活條件時可以重新啟動；壓縮歷史時正反兩邊的證據都保留在辯論膠囊（DebateCapsule）裡。MemoBrain 的三個原生動作被重新定義為科研語義：

- **Flush → Quarantine（隔離，不是清空）**——被反駁的主張不會消失，只換狀態，並記錄是誰反駁的、缺什麼證據、滿足什麼條件可以復活；
- **Fold → Dialectical Fold（辯證摺疊，不是壓縮字數）**——一場爭議只有在保留共同認識、最強支持、最強反對、鉸鏈變數、適用邊界、未解決衝突與證偽條件之後，才被摺疊成一個辯論膠囊，原始節點仍在，隨時可以點回原文；
- **Recall → Perspective Recall（角色化召回）**——每位科學家拿到的是自己的私有過程記憶 + 從同一張證據圖生成的、專屬於自己關注維度的切片：因果專家看到混雜和反向因果，測量專家看到構念衝突。

而**你的記憶**，存在知識庫裡。上傳的 PDF、Word、PPT、Excel、CSV，乃至直接貼上進來的文字，都會被解析、儲存、跨任務重用——這是屬於研究者的長期記憶：一次整理，長期生效。任務關聯知識庫後，議會在取得證據時會**檢索你的知識庫**並把命中片段帶進科學家的判斷上下文（明確標註為「非正式證據」），你的文獻真正參與七人的推理，而不是躺在一個無人讀取的資料夾裡。

### 8. 認識論路由——讓證據圖自己決定下一步查什麼

議會不是機械地跑滿七輪就算完成。證據圖發現的缺口會生成**盲點懸賞**，按影響、不確定性、可調查性、新穎度和成本打分排出優先級，再廣播給七人認領——**是證據狀態在驅動下一步調查方向，而不是主持人按預定劇本依次點名發言**。這也是為什麼 Blindspot 是產品裡的一等公民物件，而不是報告末尾一段「局限性」文字。

## 二、產品優勢

- **每個關鍵判斷都能點回原文。** 每個正式 `StudyFinding` 至少綁定來源、研究、章節、頁碼（或等價定位）、原文引用、抽取 Agent 和核驗狀態，經過來源真實性、引用蘊含、方法品質三層審核才能進圖。
- **論文數量 ≠ 獨立證據數量。** 六篇論文如果共享同一份資料集或同一個實驗室的樣本，只算一份獨立證據——報告裡這兩個數字分開顯示。
- **誠實報告缺口，而不是偽造完整結果。** 模型供應商沒設定好、預算耗盡、某個席位缺席，都會在報告裡逐條列出，任務狀態顯式標記為「帶缺口完成」——空白永遠不等於沒問題。
- **證據強度分級。** Level A（全文與精確原文可得）到 Level D（網頁/新聞線索）四級全標出，Level B/C/D 不會被用來單獨支撐高置信因果結論。
- **異議永久保留，不靠多數票壓下去。** 聯合建模禁止用投票裁決科研真理；被反駁、隔離或摺疊的觀點仍可追溯，持異議的科學家會拿到一份具名的 `DissentCertificate`。
- **盲點驅動下一步調查。** 證據圖發現的缺口生成「盲點懸賞」，按影響、不確定性、可調查性打分排出優先級，再由七人認領——Blindspot 是產品裡的一等公民物件，不是報告末尾一段「局限性」文字。
- **思考鏈路可見，思維鏈不裸奔。** 議會頁展示每位科學家的完整鏈路——預承諾 → 各輪次行動 → 最終複判，原始模型推理在對應輪次下摺疊展開。系統明確標註：那是過程資料，不是證據。
- **相關不自動升級為因果。** 因果表述必須經過因果審查並明確識別局限，橫斷面資料 + 因果主張的組合會被證據門直接攔截並留痕。
- **跑完有一份可下載的最終論文。** 任務終態時整合七席終審、條件化共識與全部參考文獻，產出結構化論文（摘要 / 正文 / 參考文獻 / 局限 / 調查過程），可匯出 Markdown。
- **每個缺口都被點名，不只是計數。** 哪個席位缺席、哪個輪次未執行或失敗，全部用中文名寫出來，任務頭常駐明細。
- **四個入口，一套內核。** 網頁工作台、HTTP/SSE API、命令列 CLI、Claude Code / Codex Agent Skill，全部走同一條研究契約，沒有第二條能繞過證據門的路徑。
- **佇列可見、會話可控。** 排隊時明確告訴你前面還有幾個任務、Worker 正在跑哪個；會話歷史支援單條刪除與全部清空，你的資料你做主。

## 三、產品能力一覽

研究工作台提供八個視圖，產品中心是**證據地圖**，不是聊天框：

| 視圖 | 回答的問題 |
|---|---|
| **Research Brief** | 30 秒了解：目前判斷、證據強弱、反例、盲點和下一項該做的研究 |
| **Controversy Map** | 主張、發現、構念、邊界、衝突與盲點組成的可互動證據地圖，點擊任何節點都能看到人話版詳情與原始記錄 |
| **Audit Trail** | 完整事件帳本：誰在什麼時候做了什麼判斷、用了什麼證據 |
| **Council（議會）** | 7 名科學家並排的完整鏈路：預承諾置信度 → 各輪次行動 → 最終複判，以及條件化共識面板 |
| **Blindspot Radar** | 按影響與可調查性排列的盲點雷達圖，點擊即讀「這個盲點是什麼、輕信它有什麼後果」 |
| **Evolution View** | 主張與盲點隨證據演化的時間線 |
| **最終論文** | 整合結論、參考文獻、局限與調查過程的論文式產出，可下載 |
| **知識庫** | 你的長期記憶：上傳文獻、貼上筆記，檢索命中直接參與議會推理 |

## 四、使用方法

### 1. 網址：先看這裡

作者維護一份**公開演示實例：`http://39.96.197.238/`**（阿里雲伺服器，隨時可訪問）。想直接試用 Poliscope，打開這個地址即可；研究證據工作台在 `/workspace`，註冊一個帳號就能開始。

Poliscope 按 MIT 協議開源，你也可以自己部署，**部署後的網址取決於你的部署方式**：

- **Docker Compose 一鍵部署（推薦）**：本機預設地址是 **`http://localhost:8080/`**（`.env` 裡的 `POLISCOPE_SITE_HOST_PORT` 決定實際埠口）。
- 部署到伺服器後，把 `.env` 裡的 `POLISCOPE_SITE_ADDRESS` 改成你的網域，Caddy 自動簽發 HTTPS，網址就是你的網域。
- **打不開 `http://localhost:8080/`？** 先查兩件事：`grep POLISCOPE_SITE_HOST_PORT .env`（看實際埠口）和 `docker compose ps caddy`（看 Caddy 容器綁定）。如果 80 埠口被別的專案佔用，真地址是 `http://localhost:<PORT>/`。改了 `deploy/caddy/Caddyfile` 後要 **`docker compose up -d --build caddy`** 重建——Caddyfile 是建進映象的，不重建不生效。

根路徑 `/` 是公開落地頁；研究證據工作台在 `/workspace`——**首次訪問會看到註冊/登入頁**：註冊一個帳號即可進入（本機記住登入狀態，30 天內免登入；換機器/過期後重新登入）。

### 2. 三步開始研究

1. **進入工作台。** 打開上面的演示地址 `http://39.96.197.238/`（或你自部署的 `http://localhost:8080/`），點「進入工作台」（或直接訪問 `/workspace`）。首次使用先註冊帳號（使用者名稱 + 密碼），之後本機自動登入。
2. **建任務。** 寫清楚你的爭議問題。可選地：
   - 關聯一個**知識庫**（你的文獻作為 Level A 使用者提供源參與議會；需要整理文件時點「管理知識庫」）；
   - 上傳 **PDF**（任務級，全文核驗後按 Level A 進入證據圖）；
   - 模型不用每次填——右側欄的**模型設定**面板儲存一次，之後所有任務自動使用；不設定則用系統預設模型。

   系統會先列出可以拆開調查的幾條原子主張，勾選你關心的，點「確認並開始研究」。
3. **追蹤與匯出。** 研究過程中頁面自動跟隨議會進度：每個輪次自動切換到對應視圖，任務頭即時顯示每個缺口；跑完後可以在網頁上查看結論，也可以匯出 Markdown / JSON 報告存檔。

整個過程通常需要幾十分鐘——七人議會加上逐條核驗證據，本來就比一句話摘要慢，這是為了可靠性做出的取捨。

### 3. 議會檢查點：研究途中你可以插一句話，但不能投票

盲點懸賞輪結束後、聯合建模開始之前，任務會停下來，給你一次**方向性引導**的機會：查看七位科學家此刻的立場（預承諾置信度、更新條件、已提出的質詢），然後提交一段方向性備註（例如「優先討論跨文化適用邊界」），或者明確留空、直接繼續——兩者同樣有效。

這段文字只會作為「[研究者方向性備註，非科學判斷]」注入聯合建模的討論方向，**不參與任何證據判定**：它不改變證據門審核邏輯，不作為任何主張的證據來源，不構成對「禁止多數投票裁決科研真理」的違反——你是唯一的方向控制者，但你不是第 8 位投票的科學家。

### 4. 知識庫：你的長期記憶

工作台的「知識庫」標籤頁（有任務時在頂部標籤欄，無任務時透過首頁上方的「知識庫」分段按鈕進入）：

- 建立知識庫 → 上傳 **PDF / TXT / MD / CSV / DOCX / PPTX / XLSX**（單個 ≤ 20 MB）→ 自動解析全文並儲存；老版 .doc / .ppt / .xls 無法解析，系統會明確提示另存為新格式，不會假裝解析成功；知識庫按帳號隔離；
- 不想整理成檔案？直接**貼上文字**（標題 + 內容）也能入庫——筆記、網頁摘錄、報告片段都可以，檢索與 Level A 待遇和上傳完全一致；
- 任務建立時關聯知識庫，議會的取得輪會把你的文件作為 Level A 源核驗，並把檢索命中帶進科學家的判斷上下文；
- 刪除保護：已被任務引用或已產生證據的知識庫/文件會拒絕刪除，證據追溯不會被抹掉。

### 5. 右側欄：模型設定、Skills 與會話歷史

工作台的右側欄在任何頁面都可見，三件事（全部按帳號隔離）：

- **模型設定**：填一次 Base URL / API Key / 模型名並儲存（存伺服器，建立任務時自動套用），之後所有任務都使用它。API Key 只存伺服器、**任何頁面都不會回顯**——介面只顯示「已設定」狀態，改設定時留空即保留舊 Key。不設定則使用部署方設定的系統預設模型。任務列表和詳情裡每個任務都會標明實際使用的是**「你儲存的設定」還是「系統預設」**（懸停可見端點與模型名），設定是否生效一眼可查。
- **Skills**：把 GitHub 技能倉庫地址（如 `https://github.com/owner/skill-name`）貼到面板下方的輸入框，點「下載並新增」即可下載其 SKILL.md 並加入列表；勾選 = 啟用。啟用後新建任務預設攜帶，worker 會把技能內容注入議會 prompt 作為**「研究者提供的技能指令（非正式證據）」**——它指導科學家的調查方法，但永遠不作為證據支持或反駁主張。
- **會話歷史**：本帳號的所有研究會話按時間倒序排列，點擊即跳轉——不再需要複製貼上任務 ID，換機器、關對話後都能從歷史裡直接回來。每行可單獨刪除（兩段式確認），也可以一鍵清空全部會話。

### 6. 從程式 Agent 裡直接呼叫（Skill）

如果你平時在 Claude Code、Codex 或其它支援 `AGENTS.md` 約定的程式 Agent 裡工作，不想切換到網頁，可以直接讓 Agent 呼叫 Poliscope。倉庫裡放了四份內容一致的 Skill 副本：

```
skills/poliscope/             Claude Code 外掛內的 Skill（/plugin install 後可用）
.claude/skills/poliscope/     Claude Code 的 Agent Skill
.codex/skills/poliscope/      Codex 對應副本
.agents/skills/poliscope/     通用 AGENTS.md 約定讀取的副本
```

Skill 本質上都在呼叫同一個 `poliscope` 命令列工具（Python 3.12）。裝法三選一：

**方式一：Claude Code 裡 `/plugin install`（推薦，一條命令裝好外掛 + Skill）：**

```bash
/plugin install Fishman-free/poliscope
```

裝完後直接輸入 `/poliscope` 即可呼叫（也可以 `/plugin marketplace add Fishman-free/poliscope` 把它加進市場列表再瀏覽）。

**方式二：`npx` 零安裝執行（有 Node 18+ 即可，底層自動用倉庫 venv 或 uvx 拉取 Python CLI）：**

```bash
npx github:Fishman-free/poliscope --help
```

發布到 npm registry 後，`npx poliscope --help` 同樣可用。也可以用 Python 生態的等價物直接跑：

```bash
uvx --from "git+https://github.com/Fishman-free/poliscope.git" poliscope --help
```

**方式三：克隆倉庫常駐安裝：**

```bash
git clone https://github.com/Fishman-free/poliscope.git
cd poliscope
uv sync                       # 或者 pip install -e ".[dev]"
poliscope --help              # 能印出幫助資訊就說明裝好了
```

Skill 本身不內建任何伺服器地址，它呼叫的命令列預設連 `http://localhost:8000`（本機起的 API）。連已部署實例時每次呼叫帶 `--base-url`，並**先登入一次**：

```bash
poliscope login --base-url <URL>     # 輸入使用者名稱密碼；首次使用可用 register 註冊
```

token 儲存在 `~/.poliscope/credentials.json`（一個 base URL 一個 token，30 天過期），之後所有命令自動帶上；非互動環境（Agent 腳本）也可以直接設定 `POLISCOPE_API_TOKEN` 環境變數，優先級高於憑證檔案。本機 API 不需要登入——`poliscope health` 可以先確認 API 活著。

工作流：你用自然語言描述研究問題 → Skill 產生待確認的 Research Contract（**先給你看，不會直接提交**）→ 你確認後依序呼叫 `poliscope start`（給出建議主張）→ `poliscope confirm-claims` → `poliscope watch` / `status` → `poliscope export`。連已部署實例時先 `poliscope login` 一次（見上）。任務會回傳 `task_id`，換機器、關對話後都能接著查。

完整命令列用法（含 `pause`/`resume`、`council-preview`/`council-guidance`、`export-docs` 等全部子命令）見 [`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md)。

## 五、請誠實對待它的結論

- **它不是醫療建議。** 涉及心理健康的問題，報告裡會明確標註「這是科研輔助，不是臨床診斷」。
- **它不會為了顯得「有結論」而編結論。** 如果部署方沒設定好 AI 模型的存取權限，系統會誠實報告「未接入模型」，某些科學家的判斷會顯式標記為缺席——空白不等於沒問題，這也是它的設計原則。
- **模型置信度不是統計證據。** 報告把模型判斷、作者原話和統計推斷分開標註，不用模型置信度替代統計不確定性。
- **被反駁、被隔離的觀點不會消失。** 報告裡的分歧和反例都留著原文出處，你可以自己判斷該信哪一邊。
