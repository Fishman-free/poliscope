# Poliscope

> **閱讀語言 / Language / 語言：** [简体中文](README.md) · [繁體中文](README.zh-Hant.md) · [English](README.en.md)

> 七位 AI 科學家，一場沒有和稀泥的科研審查。歡迎來到現場。

想像一下這個場景：你正在審閱一篇「社群媒體導致青少年憂鬱」的研究。結論很漂亮，引用很齊全——但沒有人告訴你，這篇論文和另外五篇用的是同一份資料；沒有人告訴你，關鍵的因果表述其實只是相關；也沒有人告訴你，作者自己都承認沒排除反向因果。

Poliscope 就是為這個場景造的。它是一個面向計算社會科學爭議問題的**深度研究智慧體**：輸入一個存疑的問題，它組織 **7 名各有專長的 AI 科學家**獨立取證、互相質詢、專門找反例和漏洞，最後產出一張**結論與局限並排、證據可溯源、異議不刪除**的爭議證據地圖。

不是一段讀起來通順、但無法核驗的總結。

## 今天發布的不是「7 個聊天機器人 + 1 個總結機器人」

這是 Poliscope 最容易被誤解的地方，所以值得在第一分鐘講清楚：讓 7 個 Agent 輪流各說一段話、再讓第 8 個 Agent 寫摘要，做出來的東西看起來熱鬧，但**解決不了任何一個真實的科研盲點問題**——分歧會在總結那一步被拍平，沒人的判斷真正被別人的證據挑戰過。

Poliscope 的設計從一開始就是反著來的：先決定「一個可靠的爭議審查該有的組織結構和記憶機制是什麼樣」，再把 7 個角色放進這套結構裡。這套結構叫 **EpistemoBrain**，四個支柱：

### 支柱一：七人全程參與，成本用別的方式控制

任何一次「這個角色這次用不上」的判斷，都是在賭盲點不會出現在被跳過的那個維度。測量專家看起來和一場因果爭議無關，但自報告偏差往往就是那場因果爭議真正的根源。所以 **7 個席位在每個正式研究任務中全程參與**——每輪發言有預算、沒有新資訊就 `PASS`、語義去重後才觸發重推理、七人共享同一份檢索快取。工程上更麻煩，但換來的是「不會因為一次調度誤判，漏掉本該被發現的盲點」。

七人分別是：理論建構者、因果推斷專家、測量與構念專家、統計與複現專家、邊界與情境專家、對抗性證偽者、證據與溯源審計員。EpistemoBrain 是無投票權的組織腦——不是第 8 名科學家，也不代表任何學術立場。

### 支柱二：異議保真，議會不是投票

每個席位擁有獨立角色規格、獨立私人狀態、獨立 Private MemoBrain 和不同的證據排序權重，取證階段互不可見，先各自下判斷再交換證據——「交叉質詢」才是真的交叉質詢，不是同一個思路的複述。

**系統禁止用多數投票直接裁決科研真理。** 被反駁、被隔離的觀點不會消失，仍可追溯；最終結果表達為條件化共識，真正的分歧會被寫成異議證書（`DissentCertificate`），而不是被多數意見悄悄吞掉。你可以在網頁上看到每一次質詢、每一次立場變化、每一位科學家最後堅持了什麼。

### 支柱三：雙圖治理——過程和結論必須分開存放

七人在取證、質詢、犯錯、走彎路的全過程都會被記下來（Process Graph，由 MemoBrain 管理），但這些「過程」不能自動變成「事實」——不然一個科學家一時的錯誤猜測，可能悄悄升級成報告裡的正式結論。

所以所有正式修改必須先寫入**科研事件帳本**（Scientific Event Ledger），再由唯一的寫入者 **Graph Projector** 審核後落地到 **Evidence Graph**。這一步在資料庫權限層面強制，不是靠程式碼自律——七名科學家在資料庫層面根本沒有寫證據圖的權限。

### 支柱四：長期記憶與智慧檢索

七人議會的執行記憶基座是 [MemoBrain](https://github.com/qhjqhj00/MemoBrain)：每位科學家有獨立的私人記憶，按各自角色取景地回憶證據；被反駁的假設進入隔離區，滿足條件時可以復活；壓縮歷史時正反兩邊的證據都保留在辯論膠囊（`DebateCapsule`）裡。

而**你的記憶**，存在知識庫裡。上傳的 PDF、Word、PPT、Excel、CSV，乃至直接貼上進來的文字，都會被解析、儲存、跨任務重用——這是屬於研究者的長期記憶：一次整理，長期生效。任務關聯知識庫後，議會在取得證據時會**檢索你的知識庫**並把命中片段帶進科學家的判斷上下文（明確標註為「非正式證據」），你的文獻真正參與七人的推理，而不是躺在一個無人讀取的資料夾裡。

## 產品亮點

- **每個關鍵判斷都能點回原文。** 每個正式 `StudyFinding` 至少綁定來源、研究、章節、頁碼（或等價定位）、原文引用、抽取 Agent 和核驗狀態，經過來源真實性、引用蘊含、方法品質三層審核才能進圖。
- **論文數量 ≠ 獨立證據數量。** 六篇論文如果共享同一份資料集或同一個實驗室的樣本，只算一份獨立證據——報告裡這兩個數字分開顯示。
- **誠實報告缺口，而不是偽造完整結果。** 模型供應商沒設定好、預算耗盡、某個席位缺席，都會在報告裡逐條列出，任務狀態顯式標記為「帶缺口完成」。
- **證據強度分級。** Level A（全文與精確原文可得）到 Level D（網頁/新聞線索）四級全標出，Level B/C/D 不會被用來單獨支撐高置信因果結論。
- **思考鏈路可見。** 議會頁展示每位科學家的完整鏈路——預承諾 → 各輪次行動 → 最終複判，原始模型推理在對應輪次下摺疊展開。系統明確標註：那是過程資料，不是證據。

## 使用方法

### 網址：先看這裡

Poliscope 沒有官方託管的公共網站——它按 MIT 協議開源，**你造訪的網址取決於部署**：

- **Docker Compose 一鍵部署（推薦）**：本機預設位址是 **`http://localhost:8080/`**（`.env` 裡的 `POLISCOPE_SITE_HOST_PORT` 決定實際連接埠）。
- 部署到伺服器後，把 `.env` 裡的 `POLISCOPE_SITE_ADDRESS` 改成你的網域名稱，Caddy 自動簽發 HTTPS，網址就是你的網域名稱。
- **打不開 `http://localhost:8080/`？** 先查兩件事：`grep POLISCOPE_SITE_HOST_PORT .env`（看實際連接埠）和 `docker compose ps caddy`（看 Caddy 容器綁定）。如果 80 連接埠被別的專案佔用，真實位址是 `http://localhost:<PORT>/`。改了 `deploy/caddy/Caddyfile` 後要 **`docker compose up -d --build caddy`** 重建——Caddyfile 是構建進映像的，不重建不生效。

根路徑 `/` 是公開落地頁；研究證據工作台在 `/workspace`——**首次造訪會看到註冊/登入頁**：註冊一個帳號即可進入（本機記住登入狀態，30 天內免登入；換機器/過期後重新登入）。帳號系統已取代舊的共享口令（`.env` 裡的 `POLISCOPE_SITE_USERNAME` / `POLISCOPE_SITE_PASSWORD` 已不再使用，可刪除）。

### 三步開始研究

1. **進入工作台。** 開啟 `http://localhost:8080/`，點「進入工作台」（或直接造訪 `/workspace`）。首次使用先註冊帳號（使用者名稱 + 密碼），之後本機自動登入。
2. **建任務。** 寫清楚你的爭議問題。可選地：
   - 關聯一個**知識庫**（你的文獻作為 Level A 使用者提供來源參與議會；需要整理文件時點「管理知識庫」）；
   - 上傳 **PDF**（任務級，全文核驗後按 Level A 進入證據圖）；
   - 模型不用每次填——右側欄的**模型設定**面板儲存一次，之後所有任務自動使用；不設定則用系統預設模型。
   
   系統會先列出可以拆開調查的幾條原子主張，勾選你關心的，點「確認並開始研究」。
3. **追蹤與匯出。** 研究過程中頁面自動跟隨議會進度：每個輪次自動切換到對應檢視，盲點懸賞輪結束後你還有一次**方向調整機會**（可提交一段方向性備註，或明確留空繼續）。跑完後可以在網頁上檢視結論，也可以匯出 Markdown / JSON 報告存檔。

整個過程通常需要幾十分鐘——七人議會加上逐條核驗證據，本來就比一句話摘要慢，這是為了可靠性做出的取捨。

### 知識庫：你的長期記憶

工作台的「知識庫」標籤頁（有任務時在頂部標籤列，無任務時透過首頁上方的「知識庫」分段按鈕進入）：

- 建立知識庫 → 上傳 **PDF / TXT / MD / CSV / DOCX / PPTX / XLSX**（單個 ≤ 20 MB）→ 自動解析全文並儲存；舊版 .doc / .ppt / .xls 無法解析，系統會明確提示另存為新格式，不會假裝解析成功；知識庫依帳號隔離；
- 不想整理成檔案？直接**貼上文字**（標題 + 內容）也能入庫——筆記、網頁摘錄、報告片段都可以，檢索與 Level A 待遇和上傳完全一致；
- 任務建立時關聯知識庫，議會的取得輪會把你的文件作為 Level A 來源核驗，並把檢索命中帶進科學家的判斷上下文；
- 關鍵字檢索為 Postgres 全文檢索 + 子字串比對：英文享受詞幹比對，**中文為子字串比對**（檢索定位在段落內展開原文，不做斷詞，這是當前版本的已知邊界）；
- 刪除保護：已被任務引用或已產生證據的知識庫/文件會拒絕刪除，證據追溯不會被抹掉。

### 右側欄：模型設定、Skills 與會話歷史

工作台的右側欄在任何頁面都可見，三件事（全部依帳號隔離）：

- **模型設定**：填一次 Base URL / API Key / 模型名稱並儲存（存伺服器，建立任務時自動套用），之後所有任務都使用它。API Key 只存伺服器、**任何頁面都不會回顯**——介面只顯示「已設定」狀態，改設定時留空即保留舊 Key。不設定則使用部署方設定的系統預設模型。
- **Skills**：把 GitHub 技能倉庫網址（如 `https://github.com/owner/skill-name`）貼上到面板下方的輸入框，點擊「下載並新增」即可下載其 SKILL.md 並加入清單；勾選 = 啟用。啟用後新建任務預設攜帶，worker 會把技能內容注入議會 prompt 作為**「研究者提供的技能指令（非正式證據）」**——它指導科學家的調查方法，但永遠不作為證據支持或反駁主張。
- **會話歷史**：本帳號的所有研究會話依時間倒序排列，點擊即跳轉——不再需要複製貼上任務 ID，換機器、關對話後都能從歷史裡直接回來。

### Skill 使用方法：從程式設計 Agent 裡直接呼叫

如果你平時在 Claude Code、Codex 或其他支援 `AGENTS.md` 約定的程式設計 Agent 裡工作，不想切換到網頁，可以直接讓 Agent 呼叫 Poliscope。倉庫裡放了四份內容一致的 Skill 副本，供不同 Agent 環境讀取（`.claude-plugin/plugin.json` 是 Claude Code 外掛中繼資料，本身不含 SKILL.md）：

```
skills/poliscope/             Claude Code 外掛內的 Skill（/plugin install 後可用）
.claude/skills/poliscope/     Claude Code 的 Agent Skill
.codex/skills/poliscope/      Codex 對應副本
.agents/skills/poliscope/     通用 AGENTS.md 約定讀取的副本
```

Skill 本質上都在呼叫同一個 `poliscope` 命令列工具（Python 3.12）。安裝方式三選一：

**方式一：Claude Code 裡 `/plugin install`（推薦，一條命令裝好外掛 + Skill）：**

```bash
/plugin install Fishman-free/poliscope
```

裝完後直接輸入 `/poliscope` 即可呼叫（也可以 `/plugin marketplace add Fishman-free/poliscope` 把它加進市集清單再瀏覽）。

**方式二：`npx` 零安裝執行（有 Node 18+ 即可，底層自動用倉庫 venv 或 uvx 拉取 Python CLI）：**

```bash
npx github:Fishman-free/poliscope --help
```

發布到 npm registry 後，`npx poliscope --help` 同樣可用。也可以用 Python 生態系的等價物直接跑：

```bash
uvx --from "git+https://github.com/Fishman-free/poliscope.git" poliscope --help
```

**方式三：複製倉庫常駐安裝：**

```bash
git clone https://github.com/Fishman-free/poliscope.git
cd poliscope
uv sync                       # 或者 pip install -e ".[dev]"
poliscope --help              # 能列印說明資訊就表示安裝好了
```

Skill 本身不內建任何伺服器網址，它呼叫的命令列預設連 `http://localhost:8000`（本機起的 API）。連線已部署實例時每次呼叫帶 `--base-url`，並**先登入一次**：

```bash
poliscope login --base-url <URL>     # 輸入使用者名稱密碼；首次使用可用 register 註冊
```

token 儲存在 `~/.poliscope/credentials.json`（一個 base URL 一個 token，30 天過期），之後所有命令自動帶上；非互動環境（Agent 腳本）也可以直接設定 `POLISCOPE_API_TOKEN` 環境變數，優先順序高於憑證檔案。本機 API 不需要登入——`poliscope health` 可以先確認 API 活著。

工作流程：你用自然語言描述研究問題 → Skill 生成待確認的 Research Contract（**先給你看，不會直接提交**）→ 你確認後依序呼叫 `poliscope start`（給出建議主張）→ `poliscope confirm-claims` → `poliscope watch` / `status` → `poliscope export`。連線已部署實例時先 `poliscope login` 一次（見上）。任務會回傳 `task_id`，換機器、關對話後都能接著查。

> **已知的誠實缺口**：任務級 PDF 上傳介面（`POST /api/tasks/{task_id}/papers/upload`）本身能用，但 Skill 和命令列還沒有對應的封裝命令——想附帶 PDF 時需要用 curl 直接呼叫上傳介面，或者在網頁工作台操作。

## 請誠實對待它的結論

- **它不是醫療建議。** 涉及心理健康的問題，報告裡會明確標註「這是科研輔助，不是臨床診斷」。
- **登入 token 有一處已知的 URL 洩漏面。** 瀏覽器的事件流（EventSource）無法攜帶請求標頭，所以即時進度流的登入 token 會出現在 URL 查詢參數裡，進而可能被 nginx 存取日誌記錄。本機或可信網路部署影響有限；介意的話請關閉或縮短存取日誌保留時間（這是當前版本的已知邊界）。
- **它不會為了顯得「有結論」而編結論。** 如果部署方沒設定好 AI 模型的存取權限，系統會誠實報告「未接入模型」，某些科學家的判斷會顯式標記為缺席。
- **模型置信度不是統計證據。** 報告把模型判斷、作者原話和統計推斷分開標註，不用模型置信度替代統計不確定性。
- **被反駁、被隔離的觀點不會消失。** 報告裡的分歧和反例都留著原文出處，你可以自己判斷該信哪一邊。
