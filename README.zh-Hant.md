# Poliscope

> **閱讀語言 / Language / 語言：** [简体中文](README.md) · [繁體中文](README.zh-Hant.md) · [English](README.en.md)

> 七位 AI 科學家，一場沒有和稀泥的科研審查。歡迎來到現場。
>
> **線上體驗：** [https://poliscope.tech/](https://poliscope.tech/) — 作者部署的公開實例，打開即用，無需安裝
>
> **學術論文：** [《EpistemoBrain: A Seven-Scientist Council with Dual-Graph Evidence Governance for Auditable Scientific Blindspot Discovery》](docs/paper/epistemobrain_main.pdf)（ACL Findings 2026 格式；LaTeX 源見 `docs/paper/`）

想像一下：你正在審閱一篇「社群媒體導致青少年憂鬱」的研究——結論很漂亮，引用很齊全，但沒有人告訴你這篇論文和另外五篇用的是同一份資料，沒有人告訴你因果表述其實只是相關。Poliscope 就是為這個場景造的：面向計算社會科學爭議問題的**深度研究智慧體**——**7 名各有專長的 AI 科學家**獨立取證、交叉質詢、專門找反例，產出一張**結論與局限並排、證據可溯源、異議不刪除**的爭議證據地圖。

## 一、設計思路

### 1. 解決問題

讓 7 個 Agent 輪流發言、再讓第 8 個寫摘要，分歧會在總結那一步被拍平，解決不了任何真實的科研盲點。Poliscope 反著來：先設計「一個可靠的爭議審查該有的組織結構與記憶機制」，再把 7 個角色放進去。這套結構叫 **EpistemoBrain**。

### 2. 七人全程參與

7 個席位（理論建構者、因果推斷專家、測量與構念專家、統計與複現專家、邊界與情境專家、對抗性證偽者、證據與溯源審計員）在每項正式研究中**全程參與**：每輪發言有預算、沒有新資訊就 `PASS`、共享同一份檢索快取。每個席位有獨立角色規格、私人狀態、私人記憶與證據排序權重，取證階段互不可見，先各自下判斷再交換證據——交叉質詢才是真的交叉質詢。EpistemoBrain 是無投票權的組織腦，不是第 8 名科學家。

### 3. 三層科研記憶

**Private Brain**（每位科學家自己的探索過程）→ **Collective MemoBrain**（誰提出了什麼、誰攻擊了什麼、哪些爭議未解決、下一步該查什麼）→ **Evidence Graph**（可審計的爭議證據地圖，只存經過校驗的知識，不含內部思考）。

### 4. 異議保真，議會不投票

**禁止多數投票裁決科研真理。** 七輪協議：獨立預承諾 → 專業取證 → 證據交換 → 交叉質詢 → 盲點懸賞 → 聯合建模 → 最終複判。被反駁的觀點不消失、可追溯；真正的分歧寫成具名**異議證書（Dissent Certificate）**，而不是被多數意見吞掉。

### 5. 雙圖治理

過程與結論分開存放：七人的取證、犯錯、走彎路記入 **Process Graph**；正式結論必須經科研事件帳本、由唯一寫入者 **Graph Projector** 審核後，才落地到 **Evidence Graph**。這一步在資料庫權限層面強制——七名科學家根本沒有寫證據圖的權限。

### 6. 證據門

每條正式結論過六道審核：Schema → 語義去重 → 來源核驗 → 引用蘊含 → 方法品質 → 圖一致性。證據分 A–D 四級，摘要不許單獨支撐高置信因果結論；引言假設、討論段推測不許寫成實證結果；每個 `StudyFinding` 綁定來源、章節、頁碼與原文引用。

### 7. 論文數量 ≠ 獨立證據數量

六篇共享同一資料集的論文只是一份證據講了六遍。證據譜系自動識別同資料集 / 重疊樣本 / 預印本與正式版等依賴，報告同時顯示「論文數量」與「獨立證據簇數量」。

### 8. 認識論路由

證據圖暴露的缺口生成盲點懸賞，按影響、不確定性、可調查性打分排序，由七人認領——是證據狀態驅動下一步調查，而不是主持人按台本點名。Blindspot 是產品的一等公民物件，不是報告末尾的「局限性」文字。

## 二、應用場景

- **寫綜述前**：先畫一張「哪些證據支持、哪些反對、哪裡同源重複、哪裡空白」的地圖，帶著缺口清單開始閱讀。
- **評估一篇論文**：上傳 PDF 做論文審查，議會逐項指出論證不嚴謹、證據不充分、測量與樣本代表性問題，並給出改進建議。
- **設計下一步研究**：未被解決的盲點被翻譯成具體可執行的判別研究（DiscriminatingStudy）。
- **評審與答辯**：每個關鍵判斷都能點回原文位置，展示的是一個可追溯、可證偽的科研過程。
- **敏感議題**：涉及心理健康的問題，報告明確標註「科研輔助，不是臨床診斷」。

## 三、產品優勢

- **每個關鍵判斷都能點回原文**：綁定來源、章節、頁碼、原文引用，過三層審核才進圖。
- **論文數量 ≠ 獨立證據數量**：兩個數字分開顯示，看得出「共識」是七次獨立觀察還是一次觀察講了七遍。
- **誠實報告缺口**：模型沒配好、預算耗盡、席位缺席都逐條列出，任務顯式標記「帶缺口完成」——空白不等於沒問題。
- **證據強度分級**：Level A（全文可得）到 Level D（新聞線索）全標出，低級別證據不許單獨支撐高置信因果結論。
- **異議永久保留**：不靠多數票壓下去，異議者拿到具名 `DissentCertificate`。
- **盲點驅動下一步調查**：Blindspot 是一等公民物件，不是報告末尾的「局限性」。
- **思考鏈路可見，思維鏈不裸奔**：原始推理折疊在輪次下，標註「過程資料，不是證據」。
- **相關不自動升級為因果**：橫截面資料 + 因果主張的組合被證據門攔截。
- **跑完有一份可下載的最終論文**：整合七席終審與參考文獻，可匯出 Markdown。
- **四個入口，一套內核**：網頁 / API / CLI / Agent Skill 走同一條研究契約，沒有第二條繞過證據門的路徑。

## 四、產品能力

產品中心是**證據地圖**，不是聊天框。八個視圖：

| 視圖 | 回答的問題 |
|---|---|
| Research Brief | 30 秒了解當前判斷、證據強弱、反例與盲點 |
| Controversy Map | 主張、發現、衝突與盲點組成的可互動證據地圖 |
| Audit Trail | 完整事件帳本：誰在什麼時候做了什麼判斷 |
| Council | 7 名科學家的完整鏈路與條件化共識面板 |
| Blindspot Radar | 按影響與可調查性排列的盲點雷達 |
| Evolution View | 主張與盲點隨證據演化的時間線 |
| 最終論文 | 可下載的論文式產出 |
| 知識庫 | 你的長期記憶，檢索命中直接參與議會推理 |

## 五、使用方法

### 1. 網頁

打開 [https://poliscope.tech/](https://poliscope.tech/)，註冊即用。兩個功能：

- **深度研究**：輸入爭議問題，七人議會獨立取證、交叉質詢，產出可審計的證據地圖；
- **論文審查**：上傳論文（PDF / Word / PPT / Excel / HTML / TXT，≤ 20 MB），議會逐項審查論證嚴謹性與證據充分性，完成後可在「補充提問」繼續追問。

深度研究在聯合建模前有一個**有界的人類方向性檢查點**：7 名科學家完成前 5 輪後暫停，等你提交方向性備註（或留空繼續）；寬限期（預設 120 秒）內未操作，伺服器自動以「無方向性干預」繼續——研究不會因你走開而卡死。

### 2. 程式設計 Agent（Skill）

在 Claude Code / Codex 裡直接呼叫，無需切換網頁：

```bash
/plugin install Fishman-free/poliscope      # Claude Code 一條命令裝好
npx github:Fishman-free/poliscope --help    # 或 npx 零安裝（Node 18+）
```

Skill 呼叫同一個 `poliscope` 命令列工具：描述問題 → 生成 Research Contract 給你確認（先給你看，不直接提交）→ `poliscope start` → `confirm-claims` → `watch` / `status` → `export`。連已部署實例時先 `poliscope login --base-url <URL>`。完整用法見 [`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md)。

## 六、請誠實對待它的結論

- **不是醫療建議。** 涉及心理健康的問題，報告明確標註「科研輔助，不是臨床診斷」。
- **不編結論。** 模型沒配好、預算耗盡、席位缺席，都會顯式標記——空白不等於沒問題。
- **模型置信度不是統計證據。** 模型判斷、作者原話與統計推斷分開標註。
- **異議不刪除。** 被反駁、被隔離的觀點保留原文出處，可追溯。
